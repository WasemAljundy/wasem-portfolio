# Web SEO & Discoverability

## Purpose
Ensure the portfolio can be understood by search engines, social platforms, and recruiters without compromising performance or content quality.

## Trigger
Use for new routes, project case studies, resume pages, launch preparation, domain changes, metadata work, or indexing reviews.

## Workflow
### Metadata
Provide unique titles/descriptions for home and indexable case studies. Keep metadata factual and aligned with visible content. Set canonical URLs intentionally.

### Open Graph and Social
Create consistent social previews. Prefer generated cards that include name, role, project title, and restrained branding. Validate image dimensions and text safety.

### Structured Data
Add only schema supported by visible content, such as Person, WebSite, CreativeWork/SoftwareApplication where genuinely appropriate. Do not fabricate employers, ratings, awards, or organization relationships.

### Crawlability
Maintain sitemap and robots policy. Private-client pages must expose only intentionally public information. Use noindex for routes that should not appear in search.

### Semantic Content
Use one clear page topic, meaningful headings, descriptive links, image alt text, and visible text for important claims. Do not hide keyword text for crawlers.

### Technical Integrity
Prevent duplicate canonicals, broken metadata inheritance, orphaned case studies, redirect chains, and accidental staging indexing.

## Portfolio Keyword Strategy
Optimize naturally around real identity and expertise: Wasem Aljundy, Senior Flutter Engineer, Flutter, Dart, mobile engineering, Android, Firebase, architecture, performance, and selected domain expertise where supported by projects. Never keyword-stuff.

## Definition of Done
Every public route has intentional indexing status, title/description/canonical, share preview, semantic headings, and sitemap coverage when applicable. Structured data validates and contains only truthful claims.
